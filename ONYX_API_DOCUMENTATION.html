Onyx API Reference

A practical reference for the JSON API. It covers every endpoint mounted below /api, plus the public health check. The regular HTML pages are not listed because they are for browsers, not API callers.

Before you call an endpoint
  • Use the server address in place of https://onyx.example.com.
  • Every endpoint except GET /healthz needs an active browser session or a personal access token. The examples use Authorization: Bearer $ONYX_TOKEN.
  • JSON requests use Content-Type: application/json. File uploads use -F, which sends multipart/form-data.
  • Dates are ISO 8601 timestamps. IDs are integers. Example IDs, dates, and token secrets are made up.
  • A successful delete returns 204 No Content. A missing record normally returns 404; invalid input returns 422; an action that is not allowed in the item’s current state returns 409.
